# Delta

A programming language for the theory of computation, with a playground (the Pad), a website and
mobile apps. Live at `delta.nandish.dev` (v1 is served from `main` until the v2 beta).

## Source of truth: `docs/v2/`

We are building **Delta 2** on the long-lived `v2` branch. Never merge `v2` into `main` unless the
owner says so. `v1.0-final` tags the last v1.

- `docs/v2/README.md`, then `01-LANGUAGE.md` … `04-ROADMAP.md`: the plan (phases in 04 §2)
- `docs/v2/AUDIT.md`: what v1 code is kept, changed or dropped
- `docs/v2/SEMANTICS.md`: the formal meaning of every construct; the implementation follows it
- `docs/v2/QUESTIONS.md`: open questions with their status (PROPOSED / CONFIRMED / open)
- `docs/v2/PROGRESS.md`: current state and **"Next session: start here"**. Read it first, and
  update it at the end of every session
- `conformance/`: every 01-LANGUAGE.md example as a test; `xfail.txt` lists cases not passing yet

`docs/plan/` is the v1 plan: history only. Where it disagrees with `docs/v2/`, v2 wins.

## Layout (v1 code; v2 crates are planned in 02-ENGINE.md §1)

- `crates/delta-core`: models and algorithms (pure Rust, no wasm deps)
- `crates/delta-lang`: **v2** lexer (normal + machine-body modes), parser, checker, interpreter
- `crates/delta-dsl`: v1 lexer, parser, checker (the web app uses it until the Pad moves to v2)
- `crates/delta-wasm`: wasm-bindgen facade, JSON in / JSON out
- `crates/delta-cli`: native CLI (`delta run [--json] FILE` is v2; `check`/`json` are v1)
- `web/`: React 19 + TypeScript strict + Vite + Tailwind v4 (pnpm)
- `web/src/engine/pkg/`: generated by `scripts/build-wasm.sh`, never edit, never commit
- `web/src/engine/generated/`: TS types generated from Rust by `cargo test` (ts-rs), committed
- `conformance/` + `crates/delta-cli/tests/conformance.rs`: the v2 conformance suite

## Rules

- No textbook in the core: `delta-core` (and every crate except `delta-explain`) has no textbook
  words ("Theorem", "Lemma", "Definition", "Sipser", …), not even in comments. Every algorithm and
  checker rule has a stable **algorithm/rule id** (e.g. `determinize/subset`, `model/total`), and
  doc comments describe the algorithm neutrally and name its id. Citations and quotations live
  only in `delta-explain` profiles (e.g. `profiles/sipser3e.toml`), keyed by those ids. v1 code
  still has citations; they move out as each part is ported (AUDIT.md §3).
- Spec first: new syntax or semantics needs a change to `docs/v2/` (and a conformance case) first.
- "Simple Rust" (v1 03-ARCHITECTURE.md §3.1, to be revised for v2 under Q-39): index IDs, `Vec`s, owned data, one algorithm per file,
  no `unsafe`, no lifetimes in public types.
- `delta-core` and `delta-dsl` must never panic: `unwrap`, `expect`, `panic!` are denied by Clippy.
  Errors are values (`Result`).
- All engine calls from the UI go through the Web Worker (`web/src/engine/client.ts`).
